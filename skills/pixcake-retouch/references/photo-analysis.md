# 照片诊断

目标：在给方案之前，用一屏以内的文字说清这张照片“是什么、现在怎么样、能修成什么”。先跑脚本，再看图，两边对照。

```bash
python3 scripts/analyze_raw.py <照片> --out <临时目录>
```

然后用 Read 看 `<名字>_preview.jpg`，需要看直方图时看 `<名字>_analysis.png`。

## 1. 视觉清单（看预览图）

| 维度 | 看什么 | 写法示例 |
|---|---|---|
| 题材 | 人像 / 人文街拍 / 风光 / 城市建筑 / 夜景 / 静物美食 / 宠物 / 婚礼旅拍 / 室内 | “户外半身人像，旅拍” |
| 光线 | 方向（顺、侧、逆、顶）、软硬（晴天硬光、阴天柔光）、颜色（日光、金色时刻、蓝调、室内暖光、混合光、霓虹） | “傍晚侧逆光，暖色硬光，脸部背光” |
| 主体与环境 | 主体在哪、占多大、背景是否杂乱、有没有穿帮和路人 | “主体居中偏左，背景右侧有路人和垃圾桶” |
| 色彩 | 主色有几种、冷暖关系、有没有杂色抢眼、肤色状态 | “绿+暖肤色，背景有一块饱和的红色招牌抢眼；肤色偏黄” |
| 影调 | 九种影调（见下）、光比、层次、是否发灰 | “中长调，暗部死黑、亮部天空溢出” |
| 技术问题 | 曝光、溢出、偏色、噪点、畸变、水平、对焦、杂物、皮肤瑕疵 | “地平线歪约 2°；ISO 3200 有噪点” |
| 潜力 | 适合往哪种风格修，哪种不适合 | “适合暖调胶片或金色时刻；不适合日系高调（光比太大）” |

## 2. 读脚本报告

| 报告项 | 含义 | 怎么用 |
|---|---|---|
| 分析基于 | 相机内嵌预览 / 中性 RAW 渲染 / 图片文件 | 中性渲染比像素蛋糕默认显示平、暗，判断曝光时看相对关系 |
| 传感器溢出 | RAW 里已经到顶的像素比例 | > 0.5%：这些高光救不回，考虑保留纯白、局部压暗或换天空 |
| 深暗部 | 比溢出点低 9 档以上的像素 | 比例高又想大幅提亮：先降噪，或改走暗调 |
| 拍摄光源推测 | 相机白平衡与日光的比较 | 判断原始光线冷暖，决定“校正”还是“保留氛围” |
| 影调类型 | 高/中/低调 × 长/中/短调 | 见下表 |
| 亮度分布 | 死黑/暗部/中间调/亮部/高光占比 | 死黑多 → 黑位可能要抬；高光多 → 高调或过曝 |
| 黑位 / 白位 | p1 / p99 的 L*，换算成曲线 0–255 | 黑位 > 30/255 已经是哑光感；白位 < 240 是压白 |
| 溢出像素 | 渲染后到 0 或 255 的比例 | 和“传感器溢出”对比：渲染溢出多、传感器溢出少 → 高光还能拉回 |
| 四角相对中心 | 四角亮度减中心亮度 | < −10 已有暗角或背景本来就暗，就别再加暗角 |
| 整体白平衡 | 近中性像素的偏色 | 依据写着“整个区域”时参考性低；大片天空、草地会干扰 |
| 阴影/中间调/高光色偏 | 各亮度区的颜色倾向 | 已有分离色调的照片，颜色分级要顺着或先中和 |
| 鲜艳度 | Hasler–Süsstrunk colorfulness | < 33 低饱和，45–59 中等，> 82 很鲜艳 |
| 主色 | k-means 聚类 | 写配色时用：主色是什么、要压掉哪个 |
| HSL 分布 | 八色各占多少、平均色相/饱和/明度 | 决定 HSL 先动哪几种颜色（占比高的优先） |
| 疑似肤色 | 肤色范围的像素 | 只是颜色范围，木头、沙地也会算进来；人像以看图为准 |

## 3. 九种影调

按亮度中心分高调（亮）、中调、低调（暗），按亮度跨度分长调（反差大）、中调、短调（反差小）。

| 影调 | 典型画面 | 常见风格 |
|---|---|---|
| 高长调 | 亮背景 + 少量深色重点（黑发、黑衣） | 明快人像、时尚 |
| 高中调 | 明亮、层次正常 | 日系、韩系、清新 |
| 高短调 | 整体亮而柔，几乎没有深色 | 空气感、雾感、奶油风 |
| 中长调 | 亮暗都有、对比强 | 风光、街拍、商业 |
| 中中调 | 最常见的“正常”照片 | 纪实、旅拍 |
| 中短调 | 灰、平、柔 | 阴天、胶片哑光、高级灰 |
| 低长调 | 暗为主 + 强烈亮点（逆光轮廓、灯） | 暗调情绪、伦勃朗光、夜景 |
| 低中调 | 暗而有层次 | 电影感、暗调美食 |
| 低短调 | 暗而平，几乎全是暗部 | 情绪向、雾夜 |

诊断里写“现在是 X 调”，方案里写“目标是 Y 调”，两者的差就是影调部分要做的事。

## 4. 输出格式

```
**照片诊断**
- 题材/光线：……
- 色彩：……
- 影调：现在是 X 调（数据：……），……
- 需要先处理：……（溢出、偏色、噪点、歪斜、杂物）
- 适合的方向：A（推荐，原因）、B、C
```

不要把脚本报告整段贴给用户，挑和决策有关的 3–6 个数字放进诊断即可。
